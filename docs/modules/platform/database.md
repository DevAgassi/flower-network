# Database and migrations

PostgreSQL 17 through [Drizzle ORM](https://orm.drizzle.team) with the `pg` driver (ADR-1 in [init.md](../../../init.md)). Migrations are SQL files generated by drizzle-kit.

Code: [`apps/api/src/database/`](../../../apps/api/src/database/) · Migrations: [`apps/api/drizzle/`](../../../apps/api/drizzle/) · Config: [`apps/api/drizzle.config.ts`](../../../apps/api/drizzle.config.ts)

## How to use it

```ts
import { Inject } from '@nestjs/common';
import { DATABASE, type Database, type Transaction } from '../database/database.module.js';

constructor(@Inject(DATABASE) private readonly db: Database) {}

await this.db.transaction(async (tx: Transaction) => {
  // every write of one business operation goes through tx
});
```

`DatabaseModule` is global: import it once in `AppModule`, inject `DATABASE` anywhere.

## Tables of a module

1. Define tables in `apps/api/src/<module>/<module>.schema.ts`.
2. Re-export them from [`src/database/schema.ts`](../../../apps/api/src/database/schema.ts) — drizzle-kit reads only this file.
3. A module never imports another module's tables; it uses that module's service or reacts to its events.

## Conventions

- **Primary keys:** `uuid` columns holding **UUIDv7**, generated in the app: `uuid('id').primaryKey().$defaultFn(() => uuidv7())` (`uuid` package). Time-ordered like a sequence (index-friendly), reveal no row counts, and can be generated before the insert. First used by `users`.
- **Names:** tables and columns in `snake_case`, set explicitly in the schema (`varchar('password_hash')`); TypeScript properties in `camelCase`.
- **Time:** `timestamp(…, { withTimezone: true })`; `created_at` with `defaultNow()`, `updated_at` with `defaultNow()` and `$onUpdate(() => new Date())`.
- **Integration metadata:** `public_metadata` / `private_metadata` `jsonb not null default '{}'` on key tables (init.md §4.1).
- **Fixed value sets:** `pgEnum` (adding a value is a new migration with `ALTER TYPE … ADD VALUE`).
- **References between modules:** a `*.schema.ts` may import another module's table **only to declare a foreign key** — integrity stays with the database (init.md §4.1). Services still never query another module's tables. When the referenced table does not exist yet, the column is created without the key and the module that creates the table adds it (first case: `staff_locations.location_id` → `locations`, LOC-01).
- **Invariants the database can check** (lowercase email, non-negative stock) get a `check()` constraint, not only application code.

## Migration workflow

Change a `*.schema.ts` → `db:generate` → review the generated SQL → `db:migrate` → commit the schema and the migration together.

| Command                                                        | What it does                                                                                  |
| -------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `pnpm db:migrate`                                              | Builds the API, applies Drizzle migrations (table `drizzle.migrations`) and the outbox schema |
| `pnpm db:studio`                                               | Opens Drizzle Studio                                                                          |
| `pnpm --filter @flower/api db:generate`                        | Generates a migration from schema changes                                                     |
| `pnpm --filter @flower/api db:generate --custom --name=<name>` | Empty migration for hand-written SQL (extensions, views)                                      |
| `pnpm --filter @flower/api db:check`                           | Checks migration files for consistency                                                        |

`0000_enable_extensions.sql` enables `ltree` (category trees, init.md §4.2).

## How it works

- **One pool per process.** `createPool()` builds a `pg.Pool` of `DATABASE_POOL_MAX` connections; the pool connects lazily, so the app starts even when PostgreSQL is down and `GET /health` reports it.
- **Idle connection errors.** The pool has an `error` listener that only logs. Without it, an idle connection dropped by PostgreSQL (restart, failover) emits an unhandled `error` event and the whole process crashes; the pool replaces the connection by itself. Any new pool or client (Redis, BullMQ) needs the same listener — see the [journal](journal.md).
- **Shutdown.** `onApplicationShutdown` ends the pool after other providers stopped (the outbox relay releases its leases first).
- **Migrations are a separate step**, never run at application start, so several instances never race to migrate.

## Rules

- Never edit a migration that is already on `main`; add a new one.
- Money is `bigint` in kopecks, time is `timestamptz` in UTC (init.md §8).
- Writes of one business operation share one transaction; events of that operation are added to the outbox in the same transaction ([Outbox](outbox.md)).
- Use pgAdmin (http://localhost:5051) or Drizzle Studio to look at data locally.
